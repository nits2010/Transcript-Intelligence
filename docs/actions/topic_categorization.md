# Task 1 — Topic Categorization

## Goal

Map 351 noisy raw topic tags (from `summary.json → topics[]`) into 8 meaningful
canonical categories. For each category: show meeting count, avg sentiment, dominant
call type, and concrete transcript examples.

---

## Methodology: Keyword Taxonomy with Summary Fallback

### Approach chosen: Hybrid keyword matching

Each meeting's `topics[]` array contains 2–8 free-text tags generated by an LLM
during the meeting summary step. These are noisy and inconsistent
(e.g. "outage", "platform outage", "detect outage", "service outage" all mean the same thing).

**We do NOT use:**
- Embedding-based clustering (k-means, UMAP) — too opaque for a leadership audience
- LDA / topic modelling — requires tuning, unstable across small datasets
- Re-running LLM classification — expensive and slow for a batch pipeline

**We DO use:**
- A hand-crafted keyword taxonomy: `canonical category → list of keyword patterns`
- Substring matching: each keyword is checked against each raw topic string
- Scoring: a category's score = number of keyword hits across all of the meeting's topics
- Winner: the category with the highest score = primary category
- Runner-up: stored as `secondary_category` for cross-cutting analysis
- Fallback: if no topics match, we scan the full `summary` text — catches ~5% of edge cases

### Why this approach wins for this use case

| Criterion | Keyword Taxonomy | Embeddings/LDA |
|---|---|---|
| Explainability | ✅ Fully auditable | ❌ Black box |
| Speed | ✅ Milliseconds | ⚠️ Seconds to minutes |
| Controllability | ✅ Add a keyword = extend coverage | ❌ Requires retraining |
| Accuracy on small dataset | ✅ High (domain-specific keywords) | ⚠️ Needs large corpus |
| Leadership-presentable | ✅ "We look for these 10 words" | ❌ Hard to explain |

### Trade-offs acknowledged

- **False positives**: A meeting tagged `"pipeline"` could be Sales pipeline or Kafka pipeline.
  The summary fallback and secondary_category help disambiguate.
- **New topics not in taxonomy**: Any topic that doesn't match any keyword falls through.
  Monitored via the "Uncategorized" bucket — should be near zero for this dataset.
- **Multi-category meetings**: Resolved by keeping `secondary_category`. A renewal call
  that also covers compliance is labelled Renewal (primary) + Compliance (secondary).

## The 8 Canonical Categories

### 1. Compliance & Audit
**Keywords:** compliance, compliance reporting, audit, soc 2, hipaa, pci dss, iso 27001,
gdpr, cmmc, multi-framework, regulatory

**Business meaning:** Customers using AegisCloud to meet regulatory requirements.
Proactive, structured meetings — not reactive firefighting.

**Observed:** 36 meetings (largest category), avg sentiment 4.13, dominant call type: external.

**Concrete examples:**

> **[external]** *"Aegis / Redwood Clinical — ISO 27001 Preparation"* — sentiment 4.8
> Topics: `iso 27001, compliance reporting, onboarding, healthcare`
> A proactive preparation call ahead of a scheduled ISO 27001 audit. High sentiment reflects customer confidence in AegisCloud's compliance module.

> **[customer_support]** *"Support Case #3296 — Pinnacle Insurance Comply v2 Report Formatting Issue"* — sentiment 3.4
> Topics: `product bug, compliance reporting, pdf rendering, new release issue`
> A PDF rendering bug in a new Comply module release. Moderate sentiment — the issue was minor and the rep provided a workaround.

## Implementation Notes

**File:** `transcript_intelligence/categorize.py`

**Key functions:**
- `assign_category(topics, summary_text) → (primary, secondary)` — pure scoring logic
- `run_categorization(df) → df` — adds `topic_category` and `secondary_category` columns

**Output columns added to DataFrame:**
- `topic_category`: primary canonical category string
- `secondary_category`: runner-up category or None

**Chart output:** `charts/task1_topic_categories.html`
- Horizontal bar chart: x=meeting count, y=category, colour=avg sentiment (RdYlGn)
- Hover: dominant call type

## Iteration Ideas

1. **Keyword confidence score**: weight exact-match keywords higher than substring matches
2. **Call-type-aware scoring**: a "compliance" tag in an internal call may mean internal audit
   preparation — different from an external compliance review
3. **Uncategorized review loop**: pipe Uncategorized meetings to a one-shot LLM call for
   assisted labelling — feeds new keywords back into the taxonomy
4. **Multi-label support**: expose both primary + secondary categories in the UI, enabling
   filter combinations (e.g. "Renewal AND Compliance")
